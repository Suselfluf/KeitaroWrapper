# Keitaro Wrapper

Локальное веб-приложение для тестового задания Adrobot. Оно создаёт кампании с двумя потоками и редактирует состав и веса офферов существующей кампании.

## Быстрый запуск

Понадобятся [uv](https://docs.astral.sh/uv/getting-started/installation/), Python 3.12 и доступ к [учебному Keitaro](https://keitaro-for-tests.etolegko.com/admin/). В чистой копии репозитория выполните из корня проекта:

```bash
uv sync --locked
cp .env.example .env
```

Заполните `.env` перед запуском:

| Переменная | Значение |
| --- | --- |
| `KEITARO_BASE_URL` | Корневой адрес учебного Keitaro, по умолчанию `https://keitaro-for-tests.etolegko.com`. Достаточно схемы и хоста. |
| `KEITARO_API_KEY` | Ключ из личного учебного доступа. Приложение передаёт его Keitaro с сервера. `.env` игнорируется Git. |
| `KEITARO_TEST_PREFIX` | Ваш префикс в формате `test_фамилия_`, например `test_example_`. Введите завершающее подчёркивание. |
| `KEITARO_DOMAIN_ID` | ID домена из каталога `GET /admin_api/v1/domains`. |
| `KEITARO_GROUP_ID` | ID группы кампаний из `GET /admin_api/v1/groups?type=campaigns`. |
| `KEITARO_TRAFFIC_SOURCE_ID` | ID источника трафика из `GET /admin_api/v1/traffic_sources`. |
| `DATABASE_URL` | Файл SQLite. Для первого запуска оставьте `sqlite:///./data/keitaro.db`. Для другого подключения или префикса задайте отдельный файл. |

Примените миграции и запустите веб-сервер:

```bash
uv run --locked --env-file .env alembic upgrade head
uv run --locked --env-file .env uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Откройте [Кампании Keitaro](http://127.0.0.1:8765/). На странице доступны вкладки «Создать кампанию» и «Редактор офферов». Остановить сервер можно сочетанием Ctrl+C. Конфигурация предназначена для локального запуска одним процессом.

## Что проверить в интерфейсе

1. **Создание.** Введите название со своим префиксом, двухбуквенный код страны и ID действующего оффера из каталога Keitaro. После создания интерфейс покажет ID кампании и номера потоков. Первый поток перенаправляет выбранную страну на Google. Второй направляет остальных посетителей в указанный оффер. Домен, группа и источник берутся из `.env`.
2. **Редактор.** Откройте созданную кампанию по её ID. Найдите второй действующий оффер через «Найти оффер», добавьте его в поток и проверьте веса в черновике. Можно закрепить вес, отменить черновик или нажать «Отправить в Keitaro». Удалённый из потока оффер остаётся в архиве и доступен для восстановления. При повторной загрузке интерфейс показывает веса, прочитанные из Keitaro, включая сумму меньше 100%.
3. **Отказы.** Отсутствующий ID оффера вызывает сообщение об ошибке без создания кампании. При подмене состава или веса между загрузкой и отправкой редактор сообщает о конфликте и сохраняет черновик. Повторная загрузка предложит подтвердить его сброс.

Архив и закрепления сохраняются в SQLite. Черновик находится в памяти текущей вкладки. После обновления страницы загрузите потоки ещё раз.

## Проверки и история

Автоматический набор использует подставные HTTP-ответы и временные базы. Выданный ключ для него не нужен.

```bash
uv run --locked pytest -q
uv run --locked ruff check
```

Требования, инженерные решения, изменения в Git и доказательства проверок собраны в [журнале разработки](docs/development-log.md). Маршруты обёртки доступны в её [схеме OpenAPI](http://127.0.0.1:8765/docs) после запуска. Справочные маршруты и операции учебного Keitaro описаны в его [схеме OpenAPI](https://keitaro-for-tests.etolegko.com/openapi.json).
