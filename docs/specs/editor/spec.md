# Спецификация области: Редактор офферов

Area: EDITOR · Updated: 2026-11-24
Coverage: partial

## Назначение

Загрузка кампании, черновик, веса, отправка, архив и сообщения интерфейса.

## Требования

### EDITOR-R1: Загрузить существующую кампанию

Implemented by: `rg -n -e sync_campaign_route -e RedirectStreamView app/main.py app/editor.py`
WHEN пользователь загружает кампанию по ID, THE SYSTEM SHALL показать её потоки и активные офферы с текущими значениями веса из Keitaro. Поток переадресации показывается без управления офферами.

#### Сценарий: Загрузка двух потоков

- WHEN у кампании есть поток переадресации и поток с офферами весом 25% и 75%
- THEN после загрузки видны оба потока, а веса офферов совпадают со значениями Keitaro

### EDITOR-R2: Подготовить изменения состава офферов

Implemented by: `rg -n -e preview -e cancel -e restore app/static/editor.js`
WHEN пользователь добавляет существующий оффер по ID, убирает активный оффер или возвращает оффер из архива, THE SYSTEM SHALL показать результат в черновике текущего потока. WHEN пользователь отменяет черновик, THE SYSTEM SHALL вернуть состояние последней успешной загрузки или отправки.

#### Сценарий: Добавление и отмена

- WHEN пользователь находит оффер по ID, добавляет его, затем отменяет черновик
- THEN оффер сначала появляется в черновике, после отмены исчезает, состав потока в Keitaro остаётся прежним

### EDITOR-R3: Применить состав офферов к потоку

Implemented by: `rg -n -e set_stream_offers -e _publish app/editor.py`
WHEN пользователь подтверждает отправку черновика, THE SYSTEM SHALL обновить состав и веса офферов выбранного потока в Keitaro. После успешной отправки архив показывает убранные офферы с весом 0%, доступные для восстановления.

#### Сценарий: Удаление и повторное добавление

- WHEN пользователь убирает активный оффер и отправляет черновик
- THEN этого оффера нет среди активных офферов потока, его можно вернуть из архива и отправить снова

### EDITOR-R4: Рассчитать веса при изменении состава

Implemented by: `rg -n redistribute_shares app/editor_weights.py app/editor.py`
WHEN пользователь меняет состав офферов в черновике, THE SYSTEM SHALL сохранить фиксированные веса активных офферов и разделить оставшуюся долю между остальными активными офферами. При загрузке THE SYSTEM SHALL показать веса, полученные из Keitaro, включая случаи, когда сумма меньше 100%.

#### Сценарий: Зафиксирована четверть трафика

- WHEN вес одного активного оффера зафиксирован на 25%, а двум другим активным офферам нужно разделить остаток
- THEN фиксированный вес сохраняется, два других веса составляют 38% и 37% суммарно 75%

#### Сценарий: Веса после внешнего изменения

- WHEN Keitaro возвращает два оставшихся активных оффера с весом по 25%
- THEN после загрузки интерфейс показывает 25% для каждого

#### Сценарий: Фиксация без изменения состава

- WHEN пользователь фиксирует текущий вес оффера
- THEN вес отмечается как фиксированный, состав не меняется, отправка в Keitaro не происходит

### EDITOR-R5: Показать отказ и сохранить черновик

Implemented by: `rg -n -e WRITE_UNCONFIRMED -e "Keitaro отклонил" app/editor.py`
IF Keitaro отклоняет изменения потока, THE SYSTEM SHALL показать ошибку и сохранить пользовательский черновик для исправления или повторной отправки.

#### Сценарий: Ошибка отправки

- WHEN запрос сохранения возвращает ошибку
- THEN интерфейс показывает отказ, черновик остаётся видимым, успешная отправка не отображается

### EDITOR-R6: Сверить состав с Keitaro после повторной загрузки

Implemented by: `rg -n -e _remember -e ArchivedOffer app/editor.py`
WHEN пользователь заново загружает кампанию и известный оффер исчез из состава потока в Keitaro, THE SYSTEM SHALL показать его в архиве этого потока с возможностью восстановления.

#### Сценарий: Оффер сняли напрямую в Keitaro

- WHEN ранее загруженный оффер убирают из потока в Keitaro, а затем пользователь заново загружает кампанию
- THEN оффер переходит из активных в архив, веса оставшихся взяты из ответа Keitaro

### EDITOR-R7: Отказать при некорректной правке

Implemented by: `rg -n -e validate_unique_offers -e "хотя бы один" app/contracts.py app/editor_weights.py`
IF оффера нет, его ID уже активен, правка убирает последний активный оффер или для новых весов не хватает свободной доли, THE SYSTEM SHALL показать причину отказа и сохранить предыдущий черновик без записи в Keitaro.

#### Сценарий: Последний активный оффер

- WHEN в потоке остался один активный оффер и пользователь нажимает удаление
- THEN приложение сообщает, что поток должен сохранить активный оффер, состав и веса остаются прежними

#### Сценарий: Свободная доля исчерпана

- WHEN активный оффер с весом 100% зафиксирован и пользователь пытается добавить ещё один
- THEN приложение предлагает сначала освободить вес, состав и веса остаются прежними

### EDITOR-R8: Защитить от перезаписи чужих изменений

Implemented by: `rg -n -e STALE_STREAM -e OUTSIDE_TEST_PREFIX app/editor.py`
IF тестовая кампания не соответствует настроенному префиксу пользователя или Keitaro возвращает состав или веса, изменившиеся после загрузки этой кампании, THE SYSTEM SHALL отклонить отправку и сообщить причину. IF открытый черновик ещё не отправлен, THE SYSTEM SHALL запросить подтверждение перед его заменой повторной загрузкой.

#### Сценарий: Кампания изменена извне

- WHEN пользователь готовит правку, а перед отправкой другой клиент меняет состав или веса того же потока в Keitaro
- THEN приложение обнаруживает расхождение при повторном чтении перед отправкой и сохраняет черновик без записи в Keitaro

#### Сценарий: Чужая тестовая кампания

- WHEN пользователь отправляет правку в кампанию, имя которой не начинается с его настроенного префикса
- THEN приложение отклоняет отправку и сохраняет кампанию без изменений

### EDITOR-R9: Завершить показ состояния операции

Implemented by: `rg -n -e RESULT_NOTICE_DURATION_MS -e "message.firstElementChild" app/static/editor.js`
WHEN заканчивается запрос редактора, THE SYSTEM SHALL сразу убрать текст ожидания, связанный с этим запросом. Когда операция показывает сообщение об успехе или отказе, THE SYSTEM SHALL показывать его 5 секунд. Каждый новый результат получает отдельные 5 секунд. Исчезновение сообщения не изменяет черновик.

#### Сценарий: Ожидание исчезает после успеха

- WHEN редактор успешно заканчивает поиск, закрепление или перерасчёт
- THEN интерфейс показывает обновлённые данные и прекращает показывать ожидание

#### Сценарий: Отказ остаётся читаемым

- WHEN Keitaro отклоняет отправку, а пользователь оставляет редактор открытым
- THEN сообщение видно 5 секунд, после чего оно исчезает и черновик остаётся доступен

#### Сценарий: Новый результат заменяет предыдущий

- WHEN новое сообщение появляется, пока время показа предыдущего ещё не истекло
- THEN старый таймер не убирает новое сообщение и оно получает свои 5 секунд

### EDITOR-R10: Выбрать кампанию для редактора

Implemented by: `rg -n -e search_campaigns -e campaign-id app/selection.py app/templates/index.html`
WHEN пользователь вводит текст в поле «ID кампании», THE SYSTEM SHALL предложить доступные кампании с настроенным тестовым префиксом, с фильтром по ID и названию. Пользователь может выбрать предложенную кампанию или ввести точный ID. В список выводятся только ID и название кампании.

#### Сценарий: Есть две кампании с похожими названиями

- WHEN запрос совпадает с названием своей кампании и кампании с другим префиксом
- THEN список показывает только свою кампанию. Пользователь может выбрать её с клавиатуры, затем загрузить потоки.
