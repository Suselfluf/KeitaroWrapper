# ADR-0003: Проверить запись в Keitaro на отдельной тестовой кампании

Date: 2026-11-24
Status: accepted
Decided by: владелец проекта
AI Guidance Level: Strict

## Context

Открытая схема эмулятора подтверждает маршруты, но оставляет тело операций записи произвольным JSON. Требуется подтвердить реальные поля, настройки двух потоков и изменение состава офферов.

## Decision

Провести раннюю ограниченную пробу записи на одной новой кампании с собственным тестовым префиксом после приёмки макета и появления локального доступа. Сверить настройки и состав обратным чтением. Сохранить кампанию для проверки. Клиент использует ключ из локального окружения. Чужие кампании и справочники не изменяются.

## Options considered

| Вариант | Преимущество | Цена | Решение |
| --- | --- | --- | --- |
| Проба перед интеграцией | Рано выявляет несовместимые поля и состояния | Требует доступа до готовности приложения | Принято |
| Проверка на готовом приложении | Меньше отдельных шагов для запуска | Ошибка контракта обнаруживается после реализации | Отклонено |

## Consequences

Точный внешний контракт появится после пробы. Сырые служебные ответы и ключ остаются локальными. В журнал сдачи попадут обезличенные действия и результаты.

## Enforced by

| Файл или проверка | Что проверяет |
| --- | --- |
| `app/keitaro.py`, `uv run --locked pytest -q tests/test_keitaro_read.py` | Маршруты чтения, таймауты, заголовок ключа и отказ перехода по перенаправлению. |
| `uv run --locked pytest -q tests/test_keitaro.py` | Формы четырёх операций записи, отказ от повторов и перенаправлений. |

## Правила реализации

Записывать только в выделенную учебную кампанию после согласования макета. Публиковать результаты обратного чтения в обезличенном виде. Пересогласовывать обнаруженные расхождения с прикладным контрактом.
