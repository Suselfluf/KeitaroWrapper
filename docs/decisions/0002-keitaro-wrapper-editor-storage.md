# ADR-0002: SQLite хранит известные привязки офферов и закрепления

Date: 2026-11-24
Status: accepted
Decided by: владелец проекта
AI Guidance Level: Strict

## Context

Keitaro возвращает текущий состав и веса офферов. После удаления состава из Keitaro обёртка должна помнить, какой оффер был связан с потоком. Закрепление доли — настройка редактора. Неотправленный черновик нужен в текущей пользовательской вкладке.

## Decision

Использовать SQLite через SQLAlchemy, управлять схемой миграциями Alembic. Таблица `stream_offer_memory` содержит `stream_id`, `offer_id`, `pinned`, ключ — пара идентификаторов. Известные ID сохраняются при подтверждённом наблюдении, архив строится как разность сохранённых и текущих активных ID. Вес и активный состав берутся из Keitaro. Пропавший оффер теряет закрепление. Черновик до отправки хранится в памяти вкладки.

## Options considered

| Вариант | Что даёт | Цена | Решение |
| --- | --- | --- | --- |
| SQLite с памятью известных привязок | Восстановление архива и закреплений после перезапуска, одна база без отдельной службы | Неотправленный черновик теряется при обновлении вкладки | Принято |
| PostgreSQL с серверными черновиками | Продолжение редактирования из разных браузеров | Дополнительный сервис и разрешение конкурентных изменений | Отклонено для объёма задания |
| Локальное зеркало состава и весов | Часть экрана доступна при потере связи | Устаревшие данные требуют правил синхронизации | Отклонено для текущей модели |

## Consequences

Один файл базы выделяется на одно подключение и рабочий префикс. Удаление файла сбрасывает локальную историю. Архив недавнего исчезновения можно восстановить после перезапуска при сохранённом файле.

## Enforced by

## Правила реализации

Использовать утверждённые три поля и модель владения данными. Расширение схемы и перенос черновика на сервер требуют решения владельца.
