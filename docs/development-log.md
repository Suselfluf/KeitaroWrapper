# Журнал разработки

24 ноября 2026 года. Журнал связывает требования тестового с решениями и проверками, которые можно повторить из репозитория. Инструкция запуска находится в [README](../README.md#быстрый-запуск).

## Разбор задания и выбор границ

В первой части нужно создать кампанию с доменом, группой и источником и настроить два потока. Во второй части нужно загрузить существующую кампанию и изменить состав её офферов. По видео сверили поведение редактора. Состав появляется в черновике сразу, а в Keitaro меняется только после отправки. При загрузке веса `25% + 25%` сохраняются. При добавлении оффера с закреплёнными `25%` оставшаяся доля распределяется как `38% + 37%`. Открытая схема учебного Keitaro показала маршруты, однако не определяла все поля записи. [ТЗ Adrobot](https://app.notion.com/p/mnovikov/Adrobot-2b01eb78a7bb80a1b188c3a4a1cad55e) · [Видео редактора](https://youtu.be/jNloscEWCjA) · [Схема учебного Keitaro](https://keitaro-for-tests.etolegko.com/openapi.json)

## Ход реализации

1. Создали интерактивный макет двух экранов. Владелец проверил сценарии и подтвердил понятность состояний черновика, архива и отказа. Этот шаг выполнялся на демонстрационных данных.
2. Добавили настройки запуска, модели API и начальную миграцию SQLite. Применили миграцию на временной базе, подняли FastAPI и проверили откат схемы.
3. Подключили проверенные маршруты Keitaro и проверили клиент на подставном HTTP-транспорте. Для записи отдельно подтвердили формат на учебном сервере.
4. Соединили формы с приложением. На локальном стенде с отдельной SQLite прошли в Chrome создание, отказ при неверном ID, черновик, закрепление, отправку, архив, конфликт и загрузку весов с суммой 50%. При ширине 390 пикселей горизонтальная прокрутка не появилась.

## Где проверяли

- **Учебный Keitaro.** На одной выделенной кампании записали домен, группу, источник и два потока. Чтением подтвердили фильтр страны, URL Google и запасной поток. После изменения офферов прочитали `50% + 50%`, после удаления снова прочитали `100%` у оставшегося оффера. Отдельно приложение загрузило эту кампанию через свой редактор. Географическую маршрутизацию на реальном рекламном трафике эта проба не проверяла.
- **Локальные проверки приложения.** Набор тестов использует контролируемые ответы Keitaro и отдельные SQLite. Данные учебного сервера не нужны. Сетевые вызовы из браузера в сквозной проверке шли на локальное приложение. Прошли 124 теста и Ruff.
